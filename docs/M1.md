# M1 — Layered 2D editing

## M1.1: Layer foundation
Start with native DOM rendering for raster layers, retaining the existing viewport and dependency lockfile. Introduce Konva/react-konva only if transformation handles, vector editing or canvas performance justify migration; verify React 19 compatibility and lock versions first. Define a serializable document model with stable layer IDs, type, name, visibility, lock, opacity, ordering and source-space transform. Keep source image immutable, locked by default. Render layer stack at native image coordinates with a separate viewport. Support adding a second raster layer, selecting, renaming, showing/hiding, reordering and removing non-source layers. Do not claim automatic object extraction: the source is still a flat image.

Acceptance: source protected; selected layer and stack stay synchronized; visibility/order/opacity affect rendering; preserve original dimensions/alpha; imports do not leak object URLs; explicit error handling; unit tests for layer mutations and browser tests for import and stack interactions. M1.1 is in-memory; do not imply persistence.

Initial M1.1 additionally implements numerical X/Y, uniform scale and rotation for unlocked overlay layers. Interactive handles, undo/redo, persistence and export are still pending. Source is fixed at the bottom, may be hidden, and cannot be deleted or transformed. Overlay transforms are clipped to document bounds. Limits: 32 total layers and 128 MP cumulative decoded pixel count (acceptance check, not a hard memory bound).

## Next increments
- M1.2: move/rotate/scale with handles and numeric fields; source-space coordinates; undo/redo for completed edits.
- M1.3: manual polygon/lasso cutout into independent alpha layer; copy versus cut semantics; keep original untouched under edit mask. Holes are not automatically reconstructed.
- M1.4: shape and path tools with editable vertices, geometry constraints and snapping; model desired runway and building outlines.
- M1.5: brush/eraser/clone stamp on editable layers; local project save/open and deterministic PNG export. Explicitly test pixel fidelity and alpha.
- M2: manual AI handoff, structured edits and reconstruction requests; no automatic generative editing.

M1 acceptance requires all the above, including persistence and undo/redo. M3/M4 of the original roadmap cover more advanced selection and geometry; basic versions are pulled forward to M1 for the airport use case.

## Airport example
Cut out the tower and set its new size/position; draw a vector runway target outline; mark the old tower location as a reconstruction region. Use manual AI export in M2 to request realistic terrain repair, while preserving original bytes. Precise perspective or hidden building faces require reconstruction or future 3D, not merely a 2D scale operation.

## Increment: usable polygon cutout
Prioritize M1.3 copy extraction before full transform handles/history. The polygon is drawn in source coordinates and rasterized locally to a transparent cropped PNG, placed at its original bounds as an independent layer. The select tool moves visible unlocked raster layers by pointer, accounting for viewport zoom. Copy deliberately preserves old pixels in the original. For a true move, reconstruct the old location later (clone stamp, patch, or manual AI handoff). No automatic segmentation, cut/erase, shape warping or background reconstruction in this increment. Selection hit testing currently uses rectangular transformed raster bounds, including transparent areas.
